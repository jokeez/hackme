Ubuntu / Debian

Signed apt · hackme-node

Install under /opt/hackme. Keeps your .env. Branded app menu included. install.sh also drops the public pool token for your user.

curl -fsSL https://hackme.tech/apt/install.sh | sudo bash
# later (fast mirrors, not slow CDN apt fetch):
curl -fsSL https://hackme.tech/apt/upgrade.sh | sudo bash
Manual (keyring + sources) 
curl -fsSL https://hackme.tech/apt/hackme-archive-keyring.gpg \
  | sudo tee /usr/share/keyrings/hackme-archive-keyring.gpg >/dev/null
echo 'deb [signed-by=/usr/share/keyrings/hackme-archive-keyring.gpg] https://hackme.tech/apt stable main' \
  | sudo tee /etc/apt/sources.list.d/hackme.list
sudo apt update && sudo apt install hackme-node
# then enable public pool mining → #pool-token

Public pool

One-time pool token (Linux apt / .deb)

Windows Setup and the Linux tarball already include pool.miner.token. The apt .deb does not — Debian packages must not ship credentials. Without this file the node starts, but mining shows coordinator_token_required. This file is the public shared join token for the open pool (anyone may mine with it). It is not an admin/operator secret — admin APIs reject it. Same value: /dist/pool.miner.token.

1

Install the node

Use signed apt or the .deb download. Binaries land in /opt/hackme.

2

Drop the pool token

install.sh does this automatically. If you used manual apt, run the block below once.

mkdir -p ~/.config/hackme
curl -fsSL -o ~/.config/hackme/pool.miner.token \
  https://hackme.tech/dist/pool.miner.token
chmod 600 ~/.config/hackme/pool.miner.token

# restart
pkill -f '/opt/hackme/hackme' 2>/dev/null || true
bash /opt/hackme/hackme_desktop_launch.sh
# → dashboard http://127.0.0.1:8080
Not the admin token. Use the public pool worker token above — not HACKME_ADMIN_TOKEN from your local .env.

Also accepted: ~/Downloads/pool.miner.token · paste in dashboard worker start · release path /dist/release_<ver>/linux/pool.miner.token

GPU · drivers

Hardware & driver requirements

Blake3 PoH share-PPS on the public pool. Speeds below are live-matrix burn/pool GH/s — full table: BLAKE3_GPU_MATRIX.md.

  • NVIDIA — CUDA worker (workerpoh-cuda). Toolkit/driver with NVRTC; RTX 50 needs CUDA ≥12.8 (compute_120).
  • AMD — OpenCL device Blake3 (in-matrix: RX 580 2048SP PASS). Install a working ICD; host fallback is slower.
  • CPU — always available; lower GH/s than GPU class above.
  • Hunt — coverage engines (libFuzzer / AFL++) need Linux + bubblewrap. Windows ships Dig/Orders; Hunt isolation is not a Windows path today.

B2B · Local node

Orders stay on your PC

Prefer the Orders profile (Win Setup → Orders, or Linux start_hackme_orders.sh) — local node + #orders, no mining worker. Same binaries as Miner. Exchange tab embeds exchange.hackme.tech. Pool only executes work.

  1. Install above → start HackMe Orders (or Miner, then open #orders) on 127.0.0.1:8080.
  2. Dashboard → Wallet (#wallet): top up on-chain HMC for Orders. Starter HMC is 0 — no free genesis spendable. Dig/Hunt Start auto-funds prepaid escrow from that balance (Fund Orders is optional).
  3. Developer token comes with install; re-issue on the local dashboard if needed, or CLI ./hackme-fuzzing register --save (Orders folder / Linux tar).
  4. Create Dig in #orders, or CLI: ./hackme-fuzzing wizard --pack secrets --package audit · Hunt: engines auto-install on Linux update; or bash install_hunt_engines.sh --desktop then ./hackme-fuzzing hunt create ….
  5. Use gate/report URLs on http://127.0.0.1:8080 (campaign data stays on your PC).

B2B · Fuzzing CLI

hackme-fuzzing · rc19

Integrator CLI for Dig / Hunt against your local Orders node only (127.0.0.1:8080 — not hackme.tech). Channel matches installers: 0.1.0-rc19. Keep both binaries in one folder — build shells out to hackme-fuzzing-build beside it.

CLI

Build helper

hackme-fuzzing-build — compiles rust/c/cpp/zig/… sources to WASM tasks for build.
