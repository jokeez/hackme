How-to · operator guide

Fuzz campaigns & B2B final

Campaigns live under /api/fuzz/campaigns with findings, corpus, runtime telemetry, customer reports, and a machine-readable gate for CI. Customers: hackme-fuzzing wizard --pack secrets --package audit or classic --wasm guard.wasm on a local node. Optional --public-proof publishes a Proof of Fuzz facts page + README badge (crash-gate only — not a full audit). Canonical Markdown: docs/FUZZ_PRODUCT_GUIDE.md · docs/DEVELOPERS_FUZZING.md.

0. B2B customer wizard (final)

On your local node with HACKME_ADMIN_TOKEN:

hackme-fuzzing wizard --pack secrets|script_bounds|filter_utf8 [--package scan|audit|deep] [--public-proof] hackme-fuzzing wizard --wasm ./guard.wasm --package scan|audit|deep [--title "..."]
  • packs — ready detectors: secrets · script_bounds · filter_utf8 · parser parser_expat — list with hackme-fuzzing packs
  • scan — ~1 HMC · 64 units · 1 exec/unit (wasm smoke)
  • audit — ~5 HMC · 256 units · 64 exec/unit · pool + native repro path
  • deep — ~25 HMC · 2048 units · 512 exec/unit local · 64 exec/unit cap on distributed pool (coordinator replays segment on submit)
  • coverage_kind — wasm_edge_bitmap on instrumented detector guards (secrets, filter_utf8, script_bounds) — 256-byte bitmap at linear memory offset 8192 (guided scheduling, not AFL coverage); input_fingerprint on parser packs (parser_expat uses native_repro_mode: oss_upstream — ASAN stdin on pinned libexpat)
  • ABI — check(i64)→i32 or check_bytes(ptr,len)→i32 when input_mode=bytes

Returns one-time customer_report_token, report_url, gate_url. With --public-proof: proof_url + badge_url (/proof/{id}). Wizard blocks non-loopback bases (no orders on hackme.tech).

Pool fleet: hybrid miners (PoH + fuzz) claim customer work first. Safe tiers: Scan (1 exec) and Audit (64 exec). Deep on hub is cap-64 until worker attestation ships — see docs/POOL_FUZZ_DISTRIBUTED.md.

Ops release check: bash scripts/ops/fuzz_b2b_final_gate.sh → reports/fuzz-b2b-final-*/VERDICT.md

0b. Proof of Fuzz (public badge)

Opt-in transparency for a finished campaign — README badge + facts page. Crash-gate only; detector noise and secret-like payloads stay off the public page.

GET /proof/{campaign_id} → HTML facts (or ?format=json) GET /proof/{campaign_id}/badge.svg → CLEAN / FAIL badge GET /api/fuzz/campaigns/{id}/proof → same (API path)
  • Enable with public_proof: true on security-audit / wizard --public-proof.
  • Without opt-in, proof/badge require report token or admin (same as gate).
  • Disclaimer on every page: pass ≠ proven secure · not a CVE warranty.

Private full report remains /api/fuzz/campaigns/{id}/report.html + X-Hackme-Report-Token.

1. Canon / prod gate

After upgrading nodes, schema_version on GET /api/status must equal schema_expected. Followers overlay canonical economics when a remote canon URL is set.

ADMIN_TOKEN=… BASE=https://hackme.tech bash scripts/ops/run_canonical_fuzz_gate.sh

Running the gate on prod creates test campaigns; prefer a local/staging node when possible. Product docs: docs/FUZZ_PRODUCT_GUIDE.md.

2. Ship checklist

Before calling a build production-ready, keep this gate green on your node:

ADMIN_TOKEN=… BASE=http://127.0.0.1:8080 bash scripts/ops/fuzz_release_gate.sh

Optional upstream static pass: MODE=lang_static bash scripts/tests/run_daily.sh

3. Autorunner & disk

  • HACKME_FUZZ_AUTORUN — default on; set 0 to disable in-process ticking.
  • HACKME_FUZZ_AUTORUN_TICK_SEC — tick cadence (1–60).
  • HACKME_FUZZ_ARTIFACT_DIR, HACKME_FUZZ_ARTIFACT_TTL_SEC, HACKME_FUZZ_ARTIFACT_MAX_BYTES — artifact lifecycle.
  • Per campaign: config.auto_runner = false to skip autorunner for that row.

4. Customer reports (fuzz_report_v2)

Creating a campaign or POST /api/security-audit on your node returns a one-time customer_report_token. HTML reports include triage, repro_cmd, and artifact paths — replay with go run ./tools/check_repro in the repo.

Public research (no token): L1 crypto stack v3 · live campaign snapshot.

5. CI gate

GET /api/fuzz/campaigns/{id}/gate?max_critical=0&max_high=0 …

Returns pass / reasons[]. GitHub Action template: examples/github-actions/hackme-fuzz-gate.yml in the repo.

6. Housekeeping

  • POST /api/fuzz/housekeeping — global sweep (admin).
  • POST /api/fuzz/campaigns/{id}/housekeeping — per campaign.
  • POST /api/fuzz/artifacts/cleanup — filesystem cleanup.
