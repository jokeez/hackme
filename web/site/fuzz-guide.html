Campaigns live under /api/fuzz/campaigns with findings, corpus, runtime telemetry, customer reports, and a machine-readable gate for CI. Canonical Markdown: docs/FUZZ_PRODUCT_GUIDE.md in the repository.

Docs hub API reference

0. Canon / prod gate

After upgrading nodes, schema_version on GET /api/status must equal schema_expected. Followers overlay canonical economics when a remote canon URL is set.

ADMIN_TOKEN=… BASE=https://hackme.tech bash scripts/ops/run_canonical_fuzz_gate.sh

See repo docs/CANONICAL_RELEASE_CHECKS.md — running the gate on prod creates test campaigns; prefer staging when possible.

1. Ship checklist

Before calling a build production-ready, keep this gate green on your node:

ADMIN_TOKEN=… BASE=http://127.0.0.1:8080 bash scripts/ops/fuzz_release_gate.sh

Optional upstream static pass: MODE=lang_static bash scripts/tests/run_daily.sh

2. Autorunner & disk

  • HACKME_FUZZ_AUTORUN — default on; set 0 to disable in-process ticking.
  • HACKME_FUZZ_AUTORUN_TICK_SEC — tick cadence (1–60).
  • HACKME_FUZZ_ARTIFACT_DIR, HACKME_FUZZ_ARTIFACT_TTL_SEC, HACKME_FUZZ_ARTIFACT_MAX_BYTES — artifact lifecycle.
  • Per campaign: config.auto_runner = false to skip autorunner for that row.

3. Customer reports (fuzz_report_v2)

Creating a campaign or POST /api/security-audit on your node returns a one-time customer_report_token. HTML reports include triage, repro_cmd, and artifact paths — replay with go run ./tools/check_repro in the repo.

Public research (no token): L1 crypto stack v3 · live campaign snapshot.

4. CI gate

GET /api/fuzz/campaigns/{id}/gate?max_critical=0&max_high=0 …

Returns pass / reasons[] — wire into pipelines after a campaign finishes.

5. Housekeeping

  • POST /api/fuzz/housekeeping — global sweep (admin).
  • POST /api/fuzz/campaigns/{id}/housekeeping — per campaign.
  • POST /api/fuzz/artifacts/cleanup — filesystem cleanup.

6. Full API contract

Every path and payload is listed in docs/API.md (Fuzz Campaigns). The interactive summary page links there from API reference.
