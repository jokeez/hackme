Week 1 verdict

No exploitable consensus bypass surfaced. Six of seven modules produced guard signals — inputs that trip the ported boundary check (oversize push, duplicate prevout, opcode budget, witness element cap). These are expected for selective guards under detector semantics and are not CVE claims against Bitcoin Core.

  • Day 3 (MoneyRange) ran clean — 64 runs, zero guard hits, healthy coverage edges.

Methodology

  • One upstream C guard per day → WASM check(i64)→i32, built via scripts/build_upstream_l1_pack.sh.
  • Live campaigns: POST /api/security-audit → useful-PoW order + distributed workerfuzz (detector semantics).
  • Default 64 runs/day (128 on Day 6); HMC escrow on local/production node.
  • Reproduce: DAY=N bash scripts/ops/run_bitcoin30_day.sh · series doc in repo docs/BITCOIN30_SERIES.md.
Honest scope. These modules are ported excerpts of Bitcoin Core consensus checks — not a fork of bitcoind and not a substitute for Core OSS-Fuzz. A guard_signal means the WASM gate flagged a boundary-class input; triage before any disclosure to security@bitcoincore.org. Zero critical this week = no confirmed exploit path in our probe layer.
