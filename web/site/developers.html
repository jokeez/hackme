Windows integrator path

  1. Install node from Downloads — start dashboard at 127.0.0.1:8080.
  2. Download both hackme-fuzzing and hackme-fuzzing-build into the same folder.
  3. Run powershell -ExecutionPolicy Bypass -File scripts/ops/fuzzing_windows_quickstart.ps1 (from git clone) or register manually.
  4. Build WASM locally (or use an existing .wasm guard).
  5. Recommended: hackme-fuzzing wizard --wasm guard.wasm --package audit — escrow + pool + report token.
  6. Classic path: hackme-fuzzing create manifest.json or local dashboard #orders.
  7. Open report with X-Hackme-Report-Token · wire gate_url into CI.

Token on hackme.tech in the browser is for API smoke tests only — create orders on localhost.

Quick start (curl / CLI)

Copy/paste command examples 
# Recommended — B2B final (local node + admin token)
export HACKME_ADMIN_TOKEN=…
hackme-fuzzing wizard --wasm ./guard.wasm --package audit --title "My guard"
# → campaign_id, customer_report_token, report_url, gate_url

# Integrator token (orders via manifest — developer scope)
hackme-fuzzing register --save
hackme-fuzzing build -lang rust -source check.rs -out ./fuzzing-out
hackme-fuzzing create ./fuzzing-out/my-order.manifest.json
hackme-fuzzing tasks

# Public wallet is redacted on hackme.tech (no treasury address)
curl -sS https://hackme.tech/api/wallet | jq .

# Remote from_code returns HTTP 403 on hackme.tech (build WASM locally).

When your order is open, pool workers receive the WASM gate in /api/work/claim and can commit order blocks — escrow pays the solver's miner_address, not a separate bounty for "finding a CVE". Small coordinator accrual may still apply for attempts. See economics model.
