Operations

Final checklist — gates, deploy, fuzz

Before calling a cut “production final”: run the gates below, deploy deliberately, then smoke canonical + coordinator behavior. Full Markdown copy lives in the repo at docs/OPERATOR_FINAL_CHECKLIST.md.

Docs hub Economics model

1. Three layers

  • Chain — PoH blocks; retarget every 5 blocks vs 150s ideal (5×30s).
  • Coordinator — worker accounting + payouts (settlement bridges accrual → on-chain).
  • Orders / fuzz — paid workloads and campaign gates (keep these green for product credibility).

2. Fuzz product gate

Treat fuzz stack readiness as part of every release candidate:

ADMIN_TOKEN=… BASE=http://127.0.0.1:8080 bash scripts/ops/fuzz_release_gate.sh

Guide (env, tokens, CI): fuzz-guide.html · docs/FUZZ_PRODUCT_GUIDE.md

3. Infra gates (from repo root)

Predeploy expects admin token and reachable canon + coordinator URLs.

ADMIN_TOKEN=… LOCAL_BASE=http://127.0.0.1:8080 \
VPS_BASE=http://<canon>:18080 COORD_URL=http://<coord>:18081 \
bash scripts/ops/predeploy_gate.sh

Optional: RUN_CORE_GATE=1, RUN_HYBRID_SIGNER_SMOKE=1. Optional before fuzz gate: MODE=lang_static bash scripts/tests/run_daily.sh

4. Deploy site

NODE_SSH=<ssh-alias> SKIP_DIST=1 bash scripts/ops/deploy_hackme_site.sh

Include release bundles: set SKIP_DIST=0. Full stack: deploy_hackme_public_stack.sh (see script header).

5. After deploy

  • Hard-refresh https://hackme.tech/.
  • Spot-check GET /api/status on canonical (tip + economics when exposed).
  • Coordinator / settlement timers — see scripts/ops/settle_worker_payouts.sh and settlement_healthcheck.sh.

6. Deep validation

For one massive pass (long-running), follow docs/ULTIMATE_VALIDATION_RUNBOOK.md in the repository.
