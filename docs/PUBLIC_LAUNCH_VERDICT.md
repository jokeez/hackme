## 1. Вердикт по продукту «пул + worker»

| Утверждение | Вердикт |
|-------------|---------|
| Worker-mode (coordinator + claim/submit, лимиты, hybrid signer) реализован | **Да** — `cmd/coordinator/work.go`, `POST /api/worker/start`, workerpoh / bash loop |
| Канонический overlay для follower (высота/экономика из command node) | **Да** — `HACKME_PUBLIC_AUTHORITY_BASE` / канон URL, см. `pool.go` |
| Дашборд ведёт майнера на worker, локальный HTTP PoH только на command-node с флагом | **Да** — политика `handleMiningStart` + UI |
| Версия API-узла в статусе = `1.0.0-pool` | **Да** — константа `Version` в `main.go` |
| Пул как HA / multi-master | **Нет в MVP** — один координатор, failover вручную |
| Полный replay SQLite аккаунтов через P2P | **Нет** — истина кошелька в публичном режиме по **каноническому HTTP** |

## 2. Вердикт по «экономике в трёх словах»

| Слой | Что фиксирует | Кто «видит деньги» первым |
|------|----------------|----------------------------|
| **Цепь (on-chain / SQLite command node)** | PoH-блок, эмиссия в рамках правил | **Primary wallet** производящей ноды (кредит награды), не «автоматически все GPU пула» |
| **Координатор (off-chain accrual)** | Leases, accepted attempts, `payout_hmc` по формулам env / auto от `base_reward`/`target_mod` | **Учёт воркера в БД/памяти координатора** до settlement |
| **Settlement (оператор)** | Переводы на on-chain адреса из накоплений | **Кошелёк майнера** после скриптов и env (`settle_worker_payouts.sh` и т.д.) |

**Вердикт:** фраза «сеть не знает воркеров, у них 0 HMC в цепи до выплаты» — **корректна по смыслу**. Дробление «ровно 100 монет блока минус 1% между тремя шарами» — **иллюстрация**, не универсальная формула координатора (там попытки/батчи, `rewardPerM`, found bonus, опции `payoutFoundOnly`).

## 3. Что обязан сделать оператор до «публичного дня»

Уже вынесено в **`docs/OPERATOR_FINAL_CHECKLIST.md`** и **`docs/POOL_FINAL_FREEZE.md`**. Кратко:

1. **Гейты:** `predeploy_gate.sh`, `fuzz_release_gate.sh`, при смене схемы — `private_stage_gate.sh`; для прод-канона — осознанно `run_canonical_fuzz_gate.sh`.
2. **Автоматический срез репо:** `bash scripts/ops/public_release_readiness.sh` (короткие тесты) или полный `bash scripts/ops/repo_final_selfcheck.sh`.
3. **Инфра:** TLS, nginx, бэкапы `data/*.db` + БД координатора, settlement timers / healthcheck.
4. **Секреты:** токены координатора, admin, `.env` / `hackme.env` для майнеров (не вшивать в exe).
5. **Коммуникация:** новости (`web/site/assets/news.json`), Downloads (zip + SHA256SUMS), при необходимости Telegram (`docs/TELEGRAM_BOT.md`, канальный бот отдельно).

## 4. Одной командой: быстрый вердикт по репозиторию

```bash

```

С полными тестами как перед merge:

```bash
bash scripts/ops/repo_final_selfcheck.sh
```

С опросом публичного command node (read-only):

```bash
PUBLIC_RO_BASE=https://hackme.tech bash scripts/ops/public_release_readiness.sh
```

Полный merge-пакет (как в CI перед релизом): `gofmt`, `go vet`, **все** `go test ./...`, `go build ./...`, `code_quality_audit`, `bash -n` на `scripts/ops` и `scripts/lib`, сборка main, опционально `PUBLIC_RO_BASE`:

```bash
PUBLIC_RO_BASE=https://hackme.tech bash scripts/ops/repo_final_selfcheck.sh
```

Последний прогон этого пакета в репозитории: **PASS** (включая `PUBLIC_RO_BASE=https://hackme.tech`).

## 5. Когда ИИ или человек может говорить «всё готово к публичному выпуску»

Только если одновременно:

- прошли **автоматические** проверки из п. 4 (или полный selfcheck);
- закрыт **операторский** чеклист п. 3 для **конкретного** VPS/DNS;
- зафиксированы **артефакты** (версия zip/tar, SHA256, что залито на Downloads).

Без этого формулировка «100% готово» — **не вердикт**, а маркетинг.

## 6. Реклама и «какого числа стартовать»

ИИ **не может** назначить одну календарную дату без вашего факта: когда бинарь и nginx реально на проде, сколько дней soak, какой охват кампании.

**Разделение:**

| Тип активности | Условие старта |
|----------------|----------------|
| **Тихий / технич. анонс** (Discord, закрытый список, «мы в бете») | После деплоя UI+бинаря на прод + зелёный `PROFILE=canary` для `BASE=https://hackme.tech` + 2–3 дня без инцидентов. |
| **Массовая реклама** («топ-пул», платный трафик, громкие обещания) | Пока не зелёный `PROFILE=top` в `scripts/ops/top_pool_readiness_gate.sh` (сейчас узкое место — порог **`MIN_WORKERS=10`** при фактических **2** активных воркерах на координаторе), либо пока вы **осознанно не снизите** порог в скрипте / не переформулируете позиционирование как «ранний пул». |
| **Юридически/финансово значимые обещания** | Отдельно от кода: тексты оферты, риски off-chain accrual, страна аудитории — это не выводится из `go test`. |

**Практическая ориентировочная шкала (не догма):** если прод-деплой завершён **на этой неделе**, разумный минимум перед **дорогой** рекламой — **7 календарных дней** стабильного canary-гейта и мониторинга settlement / payout. Дату «X мая» без вашей даты деплоя называть было бы нечестно: зафиксируйте **D0 = день зелёного selfcheck на проде**, тогда **массовый старт ≥ D0 + 7d** (или после прохождения `PROFILE=top`, если сохраняете текущие пороги).
