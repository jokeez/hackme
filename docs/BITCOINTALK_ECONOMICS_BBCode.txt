[b][size=11pt]The #1 misconception (please read)[/size][/b]

[quote][b]“If I mine on the HackMe pool, every new block pays my GPU like a classic BTC pool.”[/b]

[b]No.[/b] HackMe separates [b]consensus emission[/b] (PoH blocks on the chain) from [b]pool accounting[/b] (coordinator + settlement). Remote workers earn through [b]accepted lease work[/b] credited off-chain, then settled on-chain — unless you yourself operate the node that appends blocks.[/quote]

[hr]

[b][size=11pt][color=#00d1ff]Three layers — one picture[/color][/size][/b]

[code]
   YOUR RIG (CPU / OpenCL / CUDA)
        |
        |  claim lease  +  submit batch (hybrid-signed)
        v
 +---------------------------+
 |   COORDINATOR (pool)    |  <-- off-chain ledger: payout_hmc, stats
 +---------------------------+
        |
        |  settlement timer / operator batch
        v
   YOUR HMC- ADDRESS  (on-chain balance after credit)

   (parallel, network-wide)

 +---------------------------+
 |   PoH CHAIN (consensus)   |  ~30s blocks, halving schedule
 +---------------------------+
        |
        |  block reward -> primary wallet of PRODUCING NODE only
        v
   operator / leader node wallet (not auto per GPU)
[/code]

[i]Three layers = three different clocks. Accrual can move every minute; chain height moves every ~30s; your wallet updates when settlement runs.[/i]

[b][size=11pt]Layer 1 — Chain (PoH emission)[/size][/b]

[b]What it is[/b]
Useful Proof-of-Work: WASM-gated nonce search, dynamic difficulty [mono]target_mod[/mono], tip grows on valid blocks.

[b]Supply cap[/b]
[table]
[tr][td][b]Max supply[/b][/td][td][b]100,000,000 HMC[/b][/td][/tr]
[tr][td][b]Genesis policy[/b][/td][td]Locked in code ([mono]policy_hash[/mono] in metrics) — no hidden mint switch[/td][/tr]
[/table]

[b]Base block reward (empty mining — no open paid order on block)[/b]
Halving every [b]2,102,400[/b] blocks (~[b]2 years[/b] at 30s/block target), then a [b]tail floor[/b]:

[b]Network-wide emission (empty mining only)[/b]
Roughly [b]120 blocks/hour[/b] × current base reward — [b]independent[/b] of how many pool workers exist.

[b]Who receives the block subsidy on-chain?[/b]
The implementation credits the node’s [b]primary wallet row[/b] (so [mono]GET /api/wallet[/mono] matches ledger state). The block may still record a [mono]minerAddress[/mono] for transparency — credits follow [b]primary wallet[/b], not a blind header split.

[b][size=11pt]Layer 2 — Coordinator (how [u]your[/u] rig earns on the public pool)[/size][/b]

[b]Official fair pool mode[/b] ([mono]payout_found_only=0[/mono], [mono]reward_auto=1[/mono], hybrid signer strict):
You earn for [b]accepted attempts[/b] inside each lease (capped by batch size), plus a [b]found bonus[/b] when you submit a valid hit.

[b]Formula[/b] (matches coordinator code + [url=https://hackme.tech/economics-model.html]site docs[/url]):

[code]
payout_per_submit  =  (paid_attempts / 1_000_000) × reward_per_m  +  found_bonus (if valid found)

reward_per_m       ≈  base_reward_hmc × 1_000_000 / target_mod
                     (auto-synced from canonical chain metrics when reward_auto=1)
[/code]

[b]Worked example[/b] (illustrative — live [mono]target_mod[/mono] moves with pool load):
[table]
[tr][td][b]base_reward_hmc[/b][/td][td][b]0.01[/b][/td][/tr]
[tr][td][b]target_mod[/b][/td][td][b]1,000,000[/b][/td][/tr]
[tr][td][b]reward_per_m[/b][/td][td]0.01 × 1,000,000 / 1,000,000 = [b]0.01 HMC[/b] per million attempts[/td][/tr]
[tr][td][b]Your batch[/b] (lease cap)[/td][td][b]4,000,000[/b] attempts accepted[/td][/tr]
[tr][td][b]Attempt payout[/b][/td][td](4M / 1M) × 0.01 = [b]0.04 HMC[/b][/td][/tr]
[tr][td][b]Valid found hit[/b][/td][td]+ [b]found_bonus[/b] (pool default often ~0.01 HMC — see [mono]/api/pool/stats[/mono])[/td][/tr]
[/table]

[i]Higher pool difficulty ([mono]target_mod[/mono]↑) lowers [mono]reward_per_m[/mono] so coordinator payouts stay tied to chain economics — not arbitrary inflation.[/i]

[b]Fairness guards on the public pool[/b]
[list]
[*][b]Hybrid Ed25519[/b] on submits when strict mode is on — reduces fake-attempt payout games.
[*][b]Per-worker lease cap[/b] — official pool configures a max concurrent leases per worker id so one rig cannot monopolize the fleet.
[*][b]429 backpressure[/b] under abuse — coordinator rejects overload instead of corrupting leases.
[*][b]Replay / stale work[/b] protection — bad submits do not accrue.
[/list]

[b]What you see locally[/b]
[list]
[*]Dashboard → [b]Unpaid worker accrual[/b] (pool paycheck meter).
[*]Pool API → [mono]total_payout_hmc[/mono], worker stats.
[*]This is [b]off-chain[/b] until settlement — not the same as wallet balance yet.
[/list]

[b][size=11pt]Layer 3 — Settlement (off-chain → on-chain)[/size][/b]

[b]Flow[/b]
[list=1]
[*]You map [mono]worker-id=HMC-youraddress[/mono] via [mono]WORKER_PAYOUT_MAP[/mono] (must match operator map on settlement host).
[*]Coordinator accumulates [mono]payout_hmc[/mono] per worker id.
[*]Operator runs [mono]settle_worker_payouts[/mono] automation (official pool: timer on the order of [b]minutes[/b], not “once a week”).
[*]Explorer / wallet shows on-chain credit to your [mono]HMC-…[/mono] address.
[/list]

[b]Rule of thumb[/b]
[color=#39ff14][b]Accrual ≠ wallet[/b][/color] until settlement completes. Always verify on [url=https://hackme.tech/pool/explorer]pool/explorer[/url] before scaling hardware spend.

[b][size=11pt]FAQ[/size][/b]

[b]Q: I found a block — why didn’t my GPU wallet jump instantly?[/b]
A: Block subsidy credited the [b]producing node’s[/b] primary wallet path. Your rig’s income is still coordinator accrual → settlement unless you run the producer yourself.

[b]Q: Does adding 1,000 miners mint more HMC per hour?[/b]
A: [b]No[/b] for base schedule — only ~120 blocks/hour. More miners compete for coordinator accrual and block-finding probability.

[b]Q: Is this an ICO or pre-mine sale?[/b]
A: [b]No ICO · no token sale.[/b] Experimental RC network — verify everything on explorer before trusting payouts.

[b]Q: Can policy change?[/b]
A: Pool coordinator knobs and settlement timing are [b]operator policy[/b] (announced on [url=https://hackme.tech/news.html]News[/url]). Chain constants require a [b]coordinated upgrade[/b] — not a silent remote toggle.
