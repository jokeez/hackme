# Спецификация цепи HackMe (MVP)

## Идентификатор сети

- **Chain ID (логический):** `hackme-dev-mainnet` (константа в коде, дублируется в `meta.chain_id` после генезиса).

## Блок

Поле JSON (хранится в SQLite целиком в колонке `json` таблицы `blocks`).

| Поле | Тип | Описание |
|------|-----|----------|
| `index` | uint64 | Высота; генезис = 0 |
| `timestamp_unix` | int64 | Unix time секунд |
| `prev_hash` | string | hex SHA-256; у генезиса — 64 символа `0` |
| `hash` | string | hex SHA-256 заголовка (см. ниже) |
| `miner_pubkey_ed25519` | string | hex-публичный ключ ноды (опционально для старых блоков без подписи) |
| `miner_sig_ed25519` | string | hex-подпись Ed25519 по строке `hash` (опционально для старых блоков без подписи) |
| `nonce` | uint64 | Для генезиса 0; зарезервировано под PoW/PoH |
| `miner_address` | string | MVP: строка вида `HMC-…` (идентификатор узла) |
| `task` | object | Задача (см. ниже) |

## Задача (Task)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Уникальный id задачи |
| `kind` | string | У генезиса: `genesis_v1`; у PoH-блоков: `poh_wasm_v1` |
| `payload` | bytes (base64 в JSON) | Произвольные данные; у генезиса — JSON-текст в байтах |
| `target_hint` | string | Человекочитаемая подсказка для PoH |

## Хэширование (нормативно для MVP)

1. Берётся структура **без поля `hash`** (и без `miner_pubkey_ed25519` / `miner_sig_ed25519`), сериализованная в JSON с фиксированными ключами (`index`, `timestamp_unix`, `prev_hash`, `nonce`, `miner_address`, `task`) — см. `internal/block/hash.go`.
2. Вычисляется **SHA-256** от этих байт.
3. `hash` = hex-строка (нижний регистр), длина 64 символа.

Любое изменение полей заголовка после вычисления требует пересчёта `hash`. Подпись блока (`miner_sig_ed25519`) валидируется отдельно по байтам строки `hash`.

## Генезис-награда

- **0 HMC** за блок #0 на адрес `miner_address` (production policy: без стартовой эмиссии).

## WASM-замок и PoH-блоки

Майнер ищет `nonce` **на CPU** нативно (`n*7+13`) или, при сборке **`-tags cuda`** и/или **`-tags opencl`** и доступных устройствах, **батчами на GPU** (тот же `eval`, см. `internal/gpupoh`, `kernels/poh_search.cu`) — по одному воркеру на GPU, общий атомарный счётчик диапазонов; **CUDA** предпочитается перед **OpenCL**, если собраны оба тега (см. `HACKME_FORCE_OPENCL`). Результат совпадает с WASM `eval`; **перед зачислением** найденный nonce проверяется одним вызовом WASM.

После успешного решения узел записывает **следующий блок** в SQLite: в заголовке `nonce` = найденное значение, в `task` — `kind: poh_wasm_v1` и JSON-payload с `nonce`, `eval`, `mod`, `formula`; при майнинге **заказа** из таблицы `tasks` в payload добавляется **`order_task_id`** (= `id` заказа). `prev_hash` и `hash` (tip) обновляются как у обычной цепи. Награда (**+0.01 HMC** по умолчанию или `reward_hmc` заказа/манифеста) начисляется в той же транзакции; счётчик прогресса заказа в `tasks` обновляется атомарно с блоком.

## Сложность PoH (`meta.poh_target_mod`)

- Смена параметров сложности в коде **не переписывает** существующую SQLite-БД. Для проверки новых правил нужен **чистый старт**: удалить `data/` или `data/hackme.db` и снова выполнить генезис (см. корневой **README.md**).
- После **генезиса** в таблице `meta` хранится пара `key = poh_target_mod`, `value` — десятичная строка `uint64`: активный модуль `M`, для которого ищется решение `eval(nonce) % M == 0`.
- Если ключа нет (старые БД до этой версии), узел трактует `M` как **1 000 000** до первой успешной записи PoH-блока.
- В JSON PoH-блока поле `task.payload.mod` **равно** тому `M`, при котором было принято это решение (для аудита и повторной проверки).
- После каждого принятого PoH-блока `poh_target_mod` записывается **в той же транзакции**, что и вставка блока. **Перерасчёт сложности** выполняется только когда высота нового блока кратна **5** (блоки 5, 10, 15…): берётся разница Unix-времени между новым блоком и блоком с индексом `height−5`, сравнивается с целевым календарным окном **5×30 с = 150 с**. Формула: `M_next = M_prev * T_ideal / T_actual` (затем clamp): быстрее цели → **больше** `M` (сложнее), медленнее → **меньше** `M`. Между такими эпохами `M` **не меняется**. Диапазон `M` задаётся в `internal/chain/retarget.go`.
- Для встроенного `eval(n)=7n+13` значение **M не должно делиться на 7**: иначе уравнение `7n+13≡0 (mod M)` неразрешимо в ℤ. После clamp узел **сдвигает** `M` на ±1 при необходимости (см. `ClampPoHTargetMod`); при чтении из БД то же правило применяется, чтобы «плохие» сохранённые значения не блокировали майнинг.

## Заказы в БД (`tasks`) и приоритет

Через **`POST /api/tasks`** загружается манифест в SQLite. Пока есть заказ со статусом **`open`** и **`reward_hmc` > 0**, майнер берёт его **раньше** синтетики и файлов `./tasks` (FIFO по `created_at`). После нужного числа PoH-блоков с `order_task_id` заказ переходит в **`completed`**.

- **Эскроу:** при создании заказа с кошелька узла (строка `wallet`, `id=1`) списывается **`reward_hmc × target_solves`** HMC; сумма хранится в колонке **`prepaid_hmc`** (аудит). Нужен уже выполненный **генезис** и достаточный баланс; иначе заказ отклоняется (**HTTP 402**).
- **`payer_ref`:** опциональная строка в манифесте (до 256 Unicode-рун) — внешний идентификатор заказчика / ссылка на аккаунт / хэш для отчётности; сохраняется в **`tasks.payer_ref`**.
- **Подпись ответа:** тело запроса (байты JSON как отправил клиент) подписывается ключом **Ed25519** узла; в ответе возвращаются **`signature_ed25519`** и **`signing_public_key_ed25519`** (см. `docs/API.md`). Ключ создаётся в **`data/node_ed25519.seed`** при первом запуске.
- **Артефакт WASM на диске:** опционально **`wasm_artifact_path`** — путь **относительно корня артефактов** (по умолчанию каталог **`tasks/artifacts/`** от рабочей директории процесса; переопределение: **`HACKME_TASK_ARTIFACT_DIR`**). Обязательно **`artifact_hash`**: **64 hex-символа SHA-256** содержимого файла `.wasm` (нижний регистр). Узел читает файл, сверяет хеш, валидирует модуль (`check(i64)->i32`), затем майнер использует те же байты, что и при **`wasm_check_hex`**. Нельзя указывать одновременно **`wasm_artifact_path`** и **`wasm_check_hex`**.
- **Отмена и refund эскроу:** в MVP **нет** — ни HTTP-эндпоинта, ни возврата **`prepaid_hmc`** на кошелёк после списания. Заказ идёт до **`completed`** (или остаётся **`open`**, пока не добит прогресс). Строковый статус **`cancelled`** в типах зарезервирован на будущий протокол (частичные выплаты, таймауты, согласование между нодами — отдельная фаза).

## Локальный манифест задачи (`./tasks/*.json`)

Узел поднимает `TaskProvider`: по умолчанию цепь использует **встроенную** синтетику (`InternalTaskProvider`), если нет открытого платного заказа в `tasks`. Папка **`tasks/`** (рядом с рабочим каталогом процесса) может содержать один или несколько файлов `*.json`; выбирается **самый новый по времени модификации** файла, имя с префиксом **`_`** игнорируется.

Минимальные поля JSON:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Обязательный идентификатор задачи (для метрик и логов). |
| `kind` | string | По умолчанию `synthetic_poh_v1` — тот же PoH, что и у встроенного провайдера (другие значения пока игнорируются при выборе файла). |
| `artifact_hash` | string | Если задан **`wasm_artifact_path`** — **обязателен**: SHA-256 файла `.wasm` (64 hex). Иначе опционально (аудит); если пусто при заказе без пути к файлу — в БД может сохраняться хеш JSON-манифеста. |
| `wasm_artifact_path` | string | Опционально: относительный путь к `.wasm` под корнем артефактов (`tasks/artifacts/` или `HACKME_TASK_ARTIFACT_DIR`). Взаимоисключающе с **`wasm_check_hex`**. |
| `timeout_ms` | int | Опционально: подсказка таймаута для будущих исполнителей. |
| `reward_hmc` | number | Опционально: если `> 0`, узел использует это значение как награду за успешный PoH-блок вместо дефолта майнера. |
| `wasm_check_hex` | string | Опционально: hex-кодированный WASM-модуль с экспортом **`check(i64)->i32`**; после нативного условия `eval(n)%M==0` вызывается `check(n)` и блок принимается только если результат ≠0. Валидация при загрузке манифеста (заказ или файл). |

Поле `task` **внутри блока** по-прежнему описывает конкретное решение PoH (`poh_wasm_v1`); манифест задаёт **контекст заказа** на стороне узла (таблица **`tasks`** в SQLite).

## Переводы HMC (transfer tx v1)

Транзакции переводов в v1 — **account-based** (не UTXO) и используют отдельную подпись пользователя.

### Формат transfer-транзакции

Минимальная единица HMC называется **Kapa**: `1 HMC = 100,000,000 Kapa`.

| Поле | Тип | Описание |
|------|-----|----------|
| `tx_type` | string | Обязательно `transfer_v1` |
| `from` | string | Адрес отправителя (`HMC-...`) |
| `to` | string | Адрес получателя (`HMC-...`), должен отличаться от `from` |
| `amount_units` | uint64 | Сумма в минимальных единицах **Kapa** (не float) |
| `fee_units` | uint64 | Комиссия в минимальных единицах **Kapa** |
| `nonce` | uint64 | Номер исходящей транзакции отправителя |
| `timestamp_unix` | int64 | Время создания tx (unix sec) |
| `memo` | string | Опционально, до 256 байт UTF-8 |
| `pubkey_ed25519` | string | Hex-публичный ключ (32 байта) |
| `sig_ed25519` | string | Hex-подпись (64 байта) по каноническим байтам tx |

### Канонические байты для подписи и tx hash

1. Для подписи берётся JSON-структура **без** `sig_ed25519`, с ключами строго в порядке:
   `tx_type`, `from`, `to`, `amount_units`, `fee_units`, `nonce`, `timestamp_unix`, `memo`, `pubkey_ed25519`.
2. Вычисляется `tx_hash = sha256(canonical_json_bytes)` (hex lowercase).
3. Подпись `sig_ed25519` считается по тем же `canonical_json_bytes`.

### Правила валидации

- `tx_type` должен быть `transfer_v1`.
- `amount_units > 0`.
- `fee_units >= min_fee_units` (из policy сети/узла).
- `from != to`.
- `pubkey_ed25519` и `sig_ed25519` обязаны быть корректной длины и формата.
- `from` должен совпадать с адресом, детерминированно полученным из `pubkey_ed25519`.
- `ed25519.Verify(pubkey, canonical_json_bytes, sig) == true`.
- `nonce` должен совпадать с ожидаемым `next_nonce` отправителя.
- Баланс отправителя должен покрывать `amount_units + fee_units`.

### Коды отклонения (rejected reason)

- `invalid_tx_type`
- `invalid_amount`
- `invalid_fee`
- `invalid_nonce`
- `invalid_signature`
- `address_pubkey_mismatch`
- `insufficient_balance`
- `duplicate_or_replay`
- `tx_too_old`
- `tx_too_far_in_future`
